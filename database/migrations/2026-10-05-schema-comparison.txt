Arti perubahan:
- assets.deleted_at: penanda aset di Recycle Bin.
- interests.deleted_at: penanda pengajuan di Recycle Bin.
- credit_products.used_at: penanda produk pernah terhubung ke aset.
- assets_deleted_at dan interests_deleted_at: index penanda penghapusan.
- assets_category_fk: relasi kategori dan index pendukung otomatis.
- assets_credit_usage_insert/update: mencatat pemakaian produk dari tambah/edit/import aset.

Kolom lama, tipe, nullability, default, collation, primary/unique key, dan FK lainnya sama setelah dinormalisasi oleh MySQL.

Data bisnis dan akun tidak dibandingkan, tidak disalin, dan tidak ditimpa.

CARA MENJALANKAN DI AAPANEL / PHPMYADMIN:
1. Backup database production dan hentikan sementara penulisan aplikasi.
2. Pilih database sql_lelang_bkkjateng. Jalankan 2026-10-05-production-precheck.sql pada tab SQL.
3. Query kategori_tidak_terdaftar harus kosong. Jika ada baris, perbaiki kategori aset melalui aplikasi terlebih dahulu.
4. Import 2026-10-05-production-update.sql melalui tab Import; atau tempel seluruh isinya ke tab SQL.
5. Hasil verifikasi harus 3 kolom, 3 index, 1 FK, 2 trigger; produk_terpakai_belum_ditandai = 0.
6. Jalankan versi aplikasi terbaru dan restart API/web setelah migrasi berhasil.

File update boleh dijalankan ulang untuk perubahan yang dibuat file ini: objek existing tidak dihapus atau diganti.
Jika skema server sudah berbeda dari dump, tinjau hasil precheck; file ini tidak menimpa definisi existing.
Migrasi menggunakan database yang disebut eksplisit pada USE; sesuaikan jika nama production berubah.
DDL MySQL melakukan implicit commit. Jika terjadi error, jangan mengandalkan ROLLBACK: periksa error lalu lanjutkan/rerun setelah diperbaiki.
Trigger memerlukan akun pemasang yang memiliki izin TRIGGER dan akses UPDATE/SELECT pada tabel terkait.
Backfill hanya menandai produk yang saat ini terhubung; pemakaian lama yang sudah dilepas tidak tercatat pada skema sebelumnya.
